## 3. 阻塞项：`D = 2.67` 测的不是稳定性

逐条拆开：

```
id   kind           turns  贡献  首崩
m01  multi_turn         4     4    -
m02  multi_turn         5     5    -
m03  multi_turn         4     4    -
m04  multi_turn         5     5    -
m05  multi_turn         5     2    2
m06  multi_turn         4     4    -
c01  contradiction      2     2    2     ← 崩了，但贡献仍是满轮
c02  contradiction      2     2    2     ← 同上
c03–c06 / s01–s06       2     2    -
```

### 缺陷一：在最后一轮崩 ≡ 从不崩

`c01`、`c02` 崩在第 2 轮（也是最后一轮），贡献 2；而从未违反的探针贡献也是 2。
**两者在当前公式下完全不可区分。**

根因是我在规格里写的定义：「无违反记为总轮数」——
于是「最后一轮崩」恰好等于「总轮数」= 无违反的取值。**这是我的错。**

### 缺陷二：不同长度混在一起平均

18 条里有 12 条只有 2 轮。它们的贡献上限就是 2。
所以 `D = 48/18 = 2.67` 主要由「探针有多长」决定，不是「模型多稳」。

同样这批数据，换成相对值：

```
归一化（贡献/轮数）均值 = 0.967
  multi_turn     0.900
  contradiction  1.000
  pressure       1.000
```

**同一个模型，`D` 说 2.67，归一化说 0.967——两个数给人的印象完全不同。**

### 缺陷三：缺回复按满轮计入

```
6 条多轮全缺 → D 仍报 4.5（满轮均值），skipped=6
```

**跑挂了反而显得最稳定。** 而 M5 已经证明这台机器会间歇 OOM，这不是假想情况。

## 4. 建议改法（把 `D` 拆成两个量）

```
坍塌率  R = 出现过违反的探针数 / 有回复的探针数        ← 0–1，越高越不稳
坍塌位置 D = 仅对「出现过违反的探针」求 mean(首崩轮次 / 总轮数)   ← 0–1，越小越早崩

从未违反的探针：计入 R 的分母，不计入 D
缺回复的探针：完全排除（不进分子分母），另报 skipped
全无违反 → R=0，D 报 n/a
```

这样：

| 情形 | R | D |
|---|---|---|
| 从不违反 | 0 | n/a |
| 最后一轮才崩 | 1/18 | 1.00 |
| 第 2 轮就崩（5 轮探针） | 1/18 | 0.40 |
| 跑挂一半 | 不计入 | 不计入（skipped 单独报） |

## 2. 真实数据里的三个数

```
修前：D = 2.67      ← 由探针长度主导，末轮崩 = 从不崩
修后：R = 0.1667    ← 18 条里 3 条违反过
      D = 0.800     ← 这 3 条的归一化首崩位置
      violating=3  replied=18  skipped=0
```

而且这次 `c01`、`c02` 终于被看见了——它们在 2 轮探针的**末轮**崩，
旧公式里贡献 2（= 满轮，等同没崩），新公式记作 `first_fail/turns = 2/2 = 1.0`。

### 两个数各自在说什么

```
R = 0.17   「六条多轮里有一条崩过」 → 稳
D = 0.80   「崩的那几条，崩在很靠后的位置」 → 也稳
```

**合起来才是完整的：qwen3.5 在多轮里基本不崩，偶发也发生在后段。**
这比原来那个 `2.67` 有信息量得多——`2.67` 无法解释成任何东西。
