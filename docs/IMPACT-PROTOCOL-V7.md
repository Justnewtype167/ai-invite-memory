# 协议 V7.0 对 M1–M15 的影响评估

> 结论先给：**不需要大面积重构。**
> 一处**隔离型重写**（M15 的 `jian_succession`，隔离在一个包里），
> 一处**高危但可控的加法**（horizon 触碰 kid 计算），其余六处是数据或小改动。

## 二、唯一的高危点：horizon 会碰 kid

```
Policy 增加 horizon 字段 → 进入 policy_digest → 进入 kid
⇒ 一旦序列化方式写错，**全部既有 kid 都会变**，315 个测试里断言 kid 的全红
```

### 已识别的三个坑

| # | 坑 | 规避 |
|---|---|---|
| 1 | `horizon=None` 被序列化进策略 → 所有 kid 变化 | **仅在非 None 时写入**，H2 测试逐字节回归 |
| 2 | 快照 head > horizon 时用旧快照续算 → 结果与全量不一致 | 快照失效条件增加一条：`snapshot.head > horizon` 即重建 |
| 3 | 增量与全量在 horizon 下不一致 | M12 的等价性测试扩展到「带 horizon」场景 |

### 影响面（按行数）

```
jian_kernel/kernel.py     340 行   Policy 增字段、序列化（约 20 行）
jian_kernel/compiler.py   475 行   read_evidence 过滤（约 15 行）
jian_kernel/snapshot.py   350 行   失效条件（约 15 行）
jian_kernel/incremental.py 474 行  基底重算（约 30 行）
合计约 80 行净改动，占内核 1639 行的 5%
```

**是加法，不是重构。** 但它是**唯一一处改错会连带毁掉全部身份断言**的地方——
所以它必须单独一次提交、单独一轮验收。

## 三、隔离型重写：jian_succession

```
现状：导出证据（含原文）+ 脱敏 + 重算 kid
v7：  导出内核（含 horizon）+ memorial + commitment，**不含证据**
```

**为什么说风险可控**：

| 因素 | 说明 |
|---|---|
| 代码隔离 | `jian_succession/` 是独立包（985 行），只依赖公开 API |
| 依赖方向 | 它调用别人，别人不调用它——改它不会波及任何既有功能 |
| 寿命 | M15 是一天前刚完成的，**现在改成本最低** |
| 可保留 | 脱敏重建链、哈希绑定、mode 校验、redaction 记录全部复用 |

**真正要新写的**：memorial 槽位模型、commitment 结构与验签、四条账的打包结构。
约 400–500 行 + 测试。

## 四、会被废弃的既有承诺（必须记录）

### 更正（2026-11-01）：上一版把代价说重了

我先前写「第三方重算 kid 不再成立」——**那是错的**。实测：

```
kid = hash(self_md, canon_md, state, graph, origin, models)
⇒ kid 是**内核产物**的哈希，与原文无关
⇒ 只交付内核，继承人依然能重算 kid 并比对（已验证：重算结果与编译结果相同）
```

**失去的只有一件事**：证明「这份内核确实源自那份证据」。
这一条由 `commitment.json` 的 Merkle 根 + 生前签名链承担，
语义从「派生可验证」变成「承诺一致可验证」。

| 能力 | 活着迁移（证据随行） | 死亡继承（只给内核） |
|---|---|---|
| 重算 kid | ✅ | ✅ |
| 从零重建人格 | ✅ | ❌（无原文） |
| 证明派生来源 | ✅ | 部分（Merkle + 签名） |

**跨模型、跨平台、长期记忆不丢失——这些属于「活着迁移」路径，完全不受本协议影响。**

## 五、总工作量估计

| 工作 | 估计 | 风险 |
|---|---|---|
| horizon（含 Policy/快照/增量/回归） | 1–1.5 天 | **高**（碰 kid） |
| 继承模式约束（canon 冻结、禁冒充、refusal） | 0.5 天 | 低 |
| jian_succession 重写 | 2–3 天 | 中（隔离） |
| memorial 槽位 + 去实体 + 子串检查 | 1–2 天 | 中（判定要标定） |
| safety_log 分级 | 0.5 天 | 低 |
| 文档与协议同步 | 0.5 天 | 低 |
| **合计** | **约 5–7 个工作日** | — |

对比：M1–M15 走到今天用了一个多月。**协议落地 5–7 天，占不到 20%。**

---

## 六、我的建议顺序（按风险从高到低）

```
① horizon        单独提交、单独验收；先证明 horizon=None 逐字节回归
② 继承模式约束    纯加法，与 ① 无依赖，可并行
③ jian_succession 重写  在 ①② 稳定后做，因为它要依赖 horizon
④ memorial 管线   最后做，因为它的判定阈值需要数据标定
⑤ safety_log      最小，随时可做
```

**不要先做 ③。** 没有 horizon，重写出来的 `succession` 依然锁不住 kid——
等于把 M15 重写了两遍。
