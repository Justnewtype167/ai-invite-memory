# RESULTS-rewrite · 让模型"想起"的两种做法（实测）

> 探针：`tools/probe_rewrite.py`
> 模型：glm4:9b / qwen3.5:9b（本地，温度 0，固定种子）
> 记忆样本：「我的狗叫阿黄，它去年走了」+ 60 条无关闲聊

---

## 一、方案 A（只给问题，让模型猜关键词）——**被推翻**

同一句问题：「你还记得我跟你提过的那件难过的事吗」

| 模型 | 提示词 | 模型输出 |
|---|---|---|
| glm4:9b | 当前 | 难过 事件 回忆 提过 记得 |
| glm4:9b | 要求具体 | 人名 动物 地点 物品 事件 |
| glm4:9b | 举例引导 | 难过 事 朋友 旅行 记念品 |
| qwen3.5:9b | 当前 | 难过的事 伤心经历 情绪低落 痛苦回忆 往事 |
| qwen3.5:9b | 要求具体 | **小明，猫，公园，雨伞，争吵** |
| qwen3.5:9b | 举例引导 | **雨夜，医院，病历本，父亲，药瓶** |

**两类失败：**

1. **抽象词**（难过/回忆/事件）——记忆里没有这些词，检索不到；
2. **编造具体事物**（小明、公园、医院、药瓶）——这些根本没发生过。

第 2 类更危险：**它会"想起"一件不存在的事。**

> **结论：只给问题、不给材料的"重写"，在 9B 模型上不成立。**

---

## 二、方案 B（给模型看真实记忆，让它生成线索）——**样本上成立**

同一句记忆，提示词改为「这是用户过去说过的一句话：……请给出 3-5 个以后别人可能用来查找这句话的线索词」：

| 模型 | 耗时 | 线索 |
|---|---|---|
| glm4:9b | 9.6 s | 狗 阿黄 去年 走了 **悲伤** 狗狗 离世 |
| qwen3.5:9b | 11.4 s | 狗 阿黄 去世 **悲伤** 宠物 |

**两个模型都给出了「悲伤」**——这正是抽象问题需要的那座桥。

配套补了同义词组（难过 ↔ 悲伤/悲痛）后，链路成立：

```
「难过的事」 → 同义词 → 悲伤 → 命中线索 → 找到「阿黄去年走了」
```

---

## 三、代价（决定它只能是"懒生成"）

| 规模 | 全量生成线索 | 可行？ |
|---|---|---|
| 200 条 | 约 33 分钟 | 勉强 |
| 2 万条 | 约 55 小时 | ❌ |
| 20 万条 | 约 23 天 | ❌ |

**所以线索只能在"值得"的时候生成：**

1. **被钉住的记忆**（用户显式说永不遗忘）——优先级最高
2. **被检索命中过的记忆**——用一次算一次，下次抽象问题就能命中
3. **最近 N 条**——最可能被追问

**成本随"实际被用到的记忆"增长，不随全库增长。**

---

## 四、确定性（同一条红线）

`make_rewriter` 第一次没有设温度，同一句话两次调用给出不同关键词：

```
第一次：难过 事 回忆
第二次：难过的事 回忆 记得 提过
```

补上 temperature=0 + seed=42 后实测两次完全相同。

**记忆检索必须可复现：同一句话问两次，得到同一条记忆。**

---

## 五、结论

```
方案 A（盲重写）：推翻。抽象词无用，编造词危险。
方案 B（看材料再生成线索）：样本成立，但只能懒生成。
确定性：已修（温度 0 + 种子），实测可复现。
```

**下一步不是把 A 调好，而是实现 B 的懒生成，并测误召率。**
