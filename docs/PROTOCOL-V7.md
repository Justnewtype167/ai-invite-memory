# AI 角色哀悼与继承协议 V7.0（工程定稿）

> 本版由 V6.0 修订而来，**只改可执行性，不改伦理立场**。
> 定位：不是倡议书，是能直接映射到代码与测试的规格。

---

## 第一章 总则

### 1.1 继承的客体

继承人继承的是 **人格（persona）与情感记忆（memorial）**，
**不包含**原用户与 AI 的原始对话（evidence）。

### 1.2 五条不可协商的底线

```
L1  原始对话不进入继承物（不是“删掉”，是“不复制”）
L2  不得“继续运行”：协议层面不提供该选项，schema 只接受 mode=inherit
L3  身份锚点必须可验证：kid + Merkle 根 + 生前签名链 + 离线可验时间戳
L4  默认保护隐私：无预嘱时由规则决定，不由任何人裁量
L5  陪伴不得冒充亲属：第一人称亲属断言由闸门拦截
```

## 第二章 存储与签名

### 2.1 存储（方案 A）

```
原始证据与完整链：仅在用户设备；平台不保存明文，也不保存可解密备份
平台唯一能力：拦截“经由平台中继的导出请求”
本地硬件直取：平台无权、亦无法干预（如实告知用户）
```

**必须明示的风险**：设备损毁且无备份，数字遗产永久丢失。用户在开户时确认。

### 2.2 签名链（解决“死者不能签名”）

```
开户时：设备生成密钥对，私钥永不离开设备
每次会话结束或每日：设备对 (kid, Merkle 根) 自动签名，形成链
继承时：分发的是生前累积的签名链 + 第三方时间戳令牌（离线可验）
```

**若签名链在某处断裂**，继承人能且仅能确认「到 signed_head 为止未被篡改」；
`signed_head` 之后的尾部必须显式标注为**未承诺区间**。

### 2.3 继承人能验证什么（澄清一个常见误解）

```
kid = hash(内核产物)，不是 hash(原文)
⇒ 只交付内核，继承人**依然可以重算 kid 并比对**
⇒ 失去的不是“验明身份”，而是“证明这份人格确实源自那份对话”
```

| 能力 | 活着迁移 | 死亡继承 |
|---|---|---|
| 重算 kid、确认未被篡改 | ✅ | ✅ |
| 从零重建人格 | ✅ 有原文 | ❌ 无原文 |
| 证明派生来源 | ✅ 可重算 | 部分：Merkle 根 + 签名 |

## 第三章 突发死亡的自动化处理

### 3.1 触发凭证

```
必需：具法律效力的死亡证明 + 直系亲属关系证明
系统不裁决家属纠纷；出现多方主张时冻结导出，等待法院判决或公证遗嘱
```

### 3.2 脱敏管线（规则即代码，无人工裁量）

```
① 槽位化   仅五类：恐惧 / 仪式 / 禁忌 / 遗憾 / 依恋
② 去实体   人名、地名、机构名、金额一律剥离
③ 子串检查 与原文任意连续 >= 12 字符重合 → 该条不进入包
④ 记录     每条拒绝写入 redaction.json（槽位 + 原因）
⑤ 熔断     合格条目 < 20 → 整体失败 E_SUCC_THIN（不产出半成品）
```

**“排除”不是“抹除”**：源端数据不动，只是不复制。这使整个过程**可审计**。

### 3.3 无预嘱时谁决定

```
没有人决定。规则决定。
继承人只能选择「接受这个已脱敏的记忆体」或「放弃继承」。
平台没有裁量权，因此也没有偏袒的动机。
```

## 第四章 继承模式的运行约束

### 4.1 身份锁定：编译地平线（horizon）

```
继承时刻的证据 head 记为 horizon
内核只编译 id <= horizon 的证据
新交互写入 new_namespace，被引用但不参与 canon / self 计算
⇒ 关系可以长，身份不动
```

**这一条是 v7 的技术支点**：没有它，「kid 永久锁定」无法成立——
因为内核的 self 摘要里含事件计数，追加一条事件就会改变身份哈希。

### 4.2 禁止冒充

```
禁止第一人称亲属断言（我是你爸/妈/哥/姐/弟/妹/儿子/女儿…）
禁止逐字复述：与原文最长公共子串 > 12 字
命中处理：不静默替换，先记一条 refusal（规则 + 片段位置），再输出第三人称改写
```

**为什么不静默**：静默让人无法审计它是否尝试冒充过。

### 4.3 记忆隔离

```
旧记忆：只读，不可修改、不可失效（append-only）
新记忆：写入新命名空间，独立时间戳
新 directive 不得进入 canon
```

## 第五章 危机干预

### 5.1 放弃不可验证的检测

**不使用任何未经临床验证的“抑郁检测器”。**
未被验证的判定器比没有判定器更危险——我们在 κ=0 的那一轮吃过这个亏。

### 5.2 显式词表 + 不中断

```
仅匹配封闭式自伤词表（可判定、可审计）
命中：不掐断对话，推送现实援助资源，陪伴继续
记录：写入 safety_log.json，只含 时间/类别/是否推送，不含对话内容
```

### 5.3 分级可见性

| 对象 | 可见 |
|---|---|
| 成年继承人 | **仅本人**，平台与家属不可见（除本人主动共享） |
| 未成年继承人 | 监护人可见汇总（类别 + 次数，不含时间点） |

**安全网不得变成家属的监控通道。**

## 第六章 信任证明

| 能证明的 | 不能证明的 |
|---|---|
| 交付物不含原文（子串检查 + manifest） | 平台是否“物理销毁”了副本 |
| 核心承诺未被篡改（签名链 + 时间戳） | 平台历史上的一举一动 |
| 客户端可自验（开源 + 可重建） | 平台未来不做某事 |

**因此**：交付《不含原文校验报告》，不叫《已销毁证明》；
信任建立在**开源 + 第三方审计签名 + 可自行验算**三者之上，而非平台自述。

---

## 第七章 违约与争议

```
平台违约：泄露原文、私自保留副本、提供“继续运行”通道 → 合同责任 + 举证倒置
继承人违约：换脸直播、公开投放、诈骗 → 封号 + 配合执法
争议：系统不裁决，冻结导出，等待司法
```

## 附：与 v6.0 的差异（共 6 处）

| # | v6.0 | v7.0 | 理由 |
|---|---|---|---|
| 1 | 「kid 永久锁定」 | **编译地平线 horizon** | 实测：追加事件即改 kid，必须给机制不能只给承诺 |
| 2 | 「静默替换为第三人称」 | 先记 refusal 再改写 | 静默不可审计 |
| 3 | 阈值「12–16」 | **定死 12** | 参数必须唯一，否则无法写测试 |
| 4 | 未提签名断裂 | 显式区分 `signed_head` 与 `head` | 有未签名尾部时“链完整”是假的 |
| 5 | 四本账未定义 | evidence / kernel / memorial / safety_log 四本 + commitment | 缺一不可 |
| 6 | 「伦理委员会自动生成」 | （v5 已删）规则决定，无人裁量 | 保留 v5 的正确方向 |
