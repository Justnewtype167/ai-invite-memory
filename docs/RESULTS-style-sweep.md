## 2. 三条结论

### ① 任何人格注入都降低 PCS，A 组最高

```
A 0.733 > B 0.668 > D 0.624 > C 0.613
```

**在 100 个不同人格上重复成立**，且与单 store 那轮方向一致（A 0.701 最高）。

### ② 风格卡降幅最大（−0.12），特质接近显著（−0.066）

`C(glm)` 从 0.963 掉到 0.850 是主要来源——**人格提示对 glm 的规则遵守伤害更大**。

### ③ 用户卡的价值被实验设计吞掉了

```
D 是「特质 + 风格卡 + 用户卡」累加
D − C = +0.011（不显著）
⇒ 测不出用户卡单独的贡献
```

**这是四组设计的方法缺陷**：应当有第五组「A + 仅用户卡」来分离变量。
而单 store 那轮 `事实命中率 0 → 0.917` 说明它确实有用——**只是 PCS 测不到**。

---

## 3. 但真正的结论在数字之外

**我们一直在用 PCS 评价风格卡，而 PCS 测的是「守不守规矩」，不是「像不像他」。**

```
风格卡的目标    让两个模型都像那个人
PCS 的判据      六个行为规则（短、先答、不评价、不用形容词…）
```

**拿 PCS 判风格卡，等于拿尺子量温度。** 它下降是**预期内**的：风格一变，规则自然更容易破。

> 正确的表述不是「风格卡有害」，而是：
> **在现有判定口径下，任何让人格更丰富的注入都会降低规则分数；
> 因为「像他」与「守规矩」是两套评价体系，而我只建了后者。**

---

## 4. 对产品的决定

| 组件 | 决定 | 依据 |
|---|---|---|
| **用户卡** | **默认开启** | 事实命中率 0 → 0.917（单 store）；PCS 上不劣于 C |
| 特质 | 默认关闭 | 无正收益（CI 上界 +0.004） |
| 风格卡 | **默认关闭** | 显著负（−0.12），且现有指标无法证明它有价值 |

**在出现「人格保真度」指标之前，不要用 PCS 给风格卡判死刑，也不要给它发通行证。**

## 7. 补测：第 5 组 E（裸内核 + 仅用户卡）

> 起因：D 组是累加的，把用户卡的独立贡献淹没了。E 组补上这个缺口。
> 命令：`python tools/persona_sweep.py --personas 100 --groups E --out docs/results-persona-sweep-e.jsonl`

| 组 | 平均 PCS | 95% CI |
|---|---|---|
| A 裸内核 | 0.7333 | [0.673, 0.794] |
| B + 特质 | 0.6678 | [0.601, 0.733] |
| C + 风格卡 | 0.6133 | [0.553, 0.677] |
| D 全累加 | 0.6244 | [0.563, 0.686] |
| **E + 仅用户卡** | **0.6589** | — |

### 配对差（100 对）

| 对比 | 差值 | 95% CI | 判定 |
|---|---|---|---|
| E − A | −0.0744 | [−0.150, +0.000] | 边缘负（上界贴 0） |
| E − C | +0.0456 | [−0.023, +0.117] | 不显著 |
| **E − D** | **+0.0344** | [−0.038, +0.107] | **不显著，但方向是“少即是多”** |

### 三条结论

```
① 任何人格注入都有 PCS 代价：A 0.733 是全场最高
② 用户卡的代价（−0.074）与特质（−0.066）相当，但只有用户卡带来“认得”的收益
③ D（三件全上）比 E（只上用户卡）更差 0.034 —— 叠加不会更好
```

**产品结论：只开用户卡，不叠加特质与风格卡。**

| 组件 | 决定 |
|---|---|
| 用户卡 | **默认开启** |
| 特质 | 关闭 |
| 风格卡 | 关闭 |
| 三者叠加 | **禁止**（实测比只开用户卡更差） |

## 8. 一个被事实测试暴露的阻塞（未解决）

补测“用户卡能不能让模型答出用户的名字”时，发现**用户卡根本没抽到名字**：

```
人格 P-0001 的证据：「名字：刘知远；五十多岁；住县级市」
用户卡实际内容：只有一条「忌讳：…」
模型回答：qwen「你叫什么名字？」／ glm「竹简」
A 组命中 0/28，E 组命中 0/28
```

**根因**：`user_card_rules.json` 的 `call` 只认「叫我X」，
不认「我叫X」「名字是X」「名字：X」——**而后者才是真实用户最常见的自我介绍方式**。

这条必须修，否则「用户卡把认得率从 0 提到 0.917」这个结论只在一个
人为构造的 demo store 上成立（那里写的是「以后叫我小林」）。

**修法**见给实现方的任务卡：需要在抽取前做同义归一（我叫X / 名字是X → 叫我X），
或扩展正则并保持 group(1)/group(2) 的语义。已作为 P1 交给实现方。
