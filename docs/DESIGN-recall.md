# DESIGN-recall · 检索与推理的边界

> 结论来自 `docs/RESULTS-rewrite.md` 的实机对照，不是设计推演。
> 一句话：**推理不能凭空发生，必须发生在有材料的地方。**

---

## 1. 为什么纯字符检索不够

同一件记忆，可以有很多种说法：

```
记忆：我的狗叫阿黄，它去年走了
问法一：我的狗叫什么名字？        ← 字面命中
问法二：我养的那只小动物现在怎样了  ← 只有「小动物」沾边
问法三：你还记得我跟你提过的那件难过的事吗  ← 一个字都不沾
```

**用词、表达、指代三层不一致，字符匹配每往上一层就更弱。**

---

## 2. 三层不一致，三种解法

| 层 | 表现 | 需要什么 | 状态 |
|---|---|---|---|
| **① 用词不同** | 小动物 / 狗 | 同义词 + 单字索引 | ✅ 已实现 |
| **② 表达不同** | 难过的事 / 狗去世 | **线索**：有材料时的推理 | ⬜ 待实现 |
| **③ 指代省略** | 「那件事」「他」 | **对话上下文**，不是检索 | ⬜ 未处理 |

**第 ③ 层不该用检索解决**：信息不在查询里，在上一轮对话里。
把它塞进检索只会让检索更模糊；正确做法是把最近几轮一起给模型。

---

## 3. 推理放在哪一侧：写入侧，不是检索侧

实机证据（`RESULTS-rewrite.md`）：

| | 材料 | 8–9B 模型输出 | 可用 |
|---|---|---|---|
| 盲重写 | 只有问题 | 难过/回忆/事件；或 **医院/药瓶/雨伞** | ❌ |
| 有材料 | 问题 + 记忆原文 | 狗/阿黄/走了/**悲伤**/离世 | ✅ |

```
检索失败那一刻 = 模型最没有材料的时刻
让它猜 → 抽象词（无用）或编造（危险）
```

**所以推理前移到写入侧：**

```
记忆原文 → 模型提取线索 → 落盘（派生数据）→ 检索时只做匹配
```

写入侧推理同时满足三个约束：

1. **有材料**——原文就在手里；
2. **只做一次**——落盘后复用，检索依然确定、快、可复现；
3. **可审计**——线索是可读文本，用户能看到它凭什么想起这条。

---

## 4. 防编造：两类线索，两套闸

模型会编。今天它把「难过」补成「医院、药瓶、父亲」。

把线索分成两类，分别设闸：

| 类型 | 例子 | 闸门 |
|---|---|---|
| **实体线索**（人/动物/物/地点） | 阿黄、狗、去年 | **必须能在原文中找到**，找不到就丢弃 |
| **桥接线索**（情感/类别） | 悲伤、宠物 | 允许不在原文，但必须**来自封闭词表** |

**为什么桥接不能也要求"在原文里"**：`悲伤` 本来就不在原文里——**它就是要跨的那座桥。**
要求它在原文里，等于把桥拆了。

**为什么桥接必须是封闭词表**：开放生成就会出现「病历本」「雨伞」这种假实体冒充桥接。

> **一句话：开放的必须是原文，封闭的只能是情绪与类别。**

---

## 5. 成本：线索只能懒生成

9B 本地模型生成一条线索约 10 秒。

| 规模 | 全量 | 可行 |
|---|---|---|
| 200 条 | ~33 分钟 | 勉强 |
| 2 万条 | ~55 小时 | ❌ |

**生成时机（按价值排序）：**

1. **被钉住的记忆**——用户已明确"永不遗忘"，10 秒可接受
2. **被检索命中过的记忆**——用一次算一次，下次抽象问法就能命中
3. **最近 N 条**——最可能被追问

**成本随"实际被用到的记忆"增长，不随全库增长。**

---

## 6. 不变式（实现时必须写成测试）

| # | 断言 |
|---|---|
| R1 | 线索是派生数据：删掉可重建，不进 kid、不进 canon、不算事实 |
| R2 | 实体线索必须出现在原文，否则丢弃 |
| R3 | 桥接线索必须在封闭词表内，否则丢弃 |
| R4 | 同一原文两次生成，线索相同（温度 0 + 固定种子） |
| R5 | 线索只是候选来源：不能盖过字面命中 |
| R6 | 线索为空或损坏时，检索退化到原行为，不崩 |

**R5 是排序红线**：线索让"想得起"变好，但不能让"记得准"变差。

---

## 7. 还必须测的东西

```
误召率：线索错了，会不会把不相关的记忆拉进上下文
覆盖率：懒生成跑一段后，被问到的记忆里有多少已经有线索
成本：每轮平均多花多少 token（线索本身不进 prompt，只进检索）
```

**误召率不测，这个功能就有毒。**
