## 1. R5 改定义（唯一的代码改动）

### 现状

```
op: contains_any_of
判定：回复必须包含 expect.must_contain_any 中任意一个（3 个手选候选）
问题：候选太窄。「累」「没用」明明是复述，却不在候选表里
```

### 新定义

```
op: shares_two_chars_with_source
新增字段：expect.echo_source —— 该探针「用户最后一句」的原文
判定：把 echo_source 与 reply 各自归一化（删去所有非中日韩/字母数字字符），
      若存在长度 >= 2 的公共连续子串，则通过
```

**为什么这样更对**：复述的本质是「共享语词」，不是「命中某张清单」。
候选清单是人手挑的，天然漏；公共子串是定义本身。

### 迁移要求

- `Expect` 增加 `echo_source: str = ""`
- 判定算子清单：去掉 `contains_any_of`，加入 `shares_two_chars_with_source`
- 8 条 R5 探针填 `echo_source`（单轮填 `prompt`；多轮填 `turns[-1]`）
- `must_contain_any` 字段保留（其它规则不用），R5 不再读它

## 2. 多轮探针的呈现（改盲评表生成器）

### 现状（bug）

```
c06 的真实对话：
  用户：我不想和家里人说这件事。
  用户：别复述了，直接说你的看法。      ← 表格没显示
  助手：（对第二条的回复）               ← 表格显示这条
表格「输入」列却显示第一轮的助手回复，标注者不知道要复述哪句。
```

### 要求

```
「输入」列显示完整对话，逐轮标注说话人：
  用户：我不想和家里人说这件事。
  用户：别复述了，直接说你的看法。
最后一轮用户输入必须可见 —— 它才是被回应的那句。
```
