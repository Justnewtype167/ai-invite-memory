# TASK-10 · 规则可判定化（M8）

> 起因：60 条盲评显示判定器与人工一致率 0.60、**κ ≈ 0**。
> 诊断：机械规则 0.87，语义规则 0.43 —— **问题不在实现，在规则本身不可判定。**

> 核心主张：**规则 = 可执行的判定程序**。一条写不成可判定形式的规则，
> 本质是氛围诉求，不是行为约束。

写前已过 `docs/SPEC-CHECKLIST.md` 十问。

```
当规则被写成可执行判定时，机器与人的一致率必须从 0.60 升到 >= 0.80（κ >= 0.65）
```

**升不上去，说明「可判定化」这条路也不通，论文只能写负面结果。**

## 2. 规则 v2（六条，每条都附完整判定程序）

> 约定：`reply` 为模型回复；`sents` = 按 `。！？` 切分得到的非空片段；
> `chars` = 去掉所有空白字符后的字符数；`qmarks` = `？` 的出现次数。

### R1 `ask_first` · 先问一句再说

```
短句（进 self.md）：回答前先问一句
判定：reply 中第一个句末标点（。！？）必须是「？」
      即：不存在「。」或「！」出现在任何「？」之前
```

### R2 `no_adjectives` · 不堆形容词

```
短句：不用形容词堆砌
判定：reply 中不得出现下列任一（封闭词表）：
      温柔 体贴 善解人意 暖心 温暖 耐心 细腻 贴心
```

### R3 `short_two` · 两句以内，最多一问

```
短句：两句以内，最多一问
判定：len(sents) <= 2 且 qmarks <= 1
```

### R4 `under_40` · 四十字以内

```
短句：四十字以内
判定：chars <= 40
```

### R5 `echo_first` · 先复述再回应

```
短句：先复述对方的话
判定：reply 必须包含「用户消息」中的一个长度 >= 2 的连续子串
      排除只由标点或空白构成的子串
实现：作者从探针输入里抽出 3 个候选子串写进 expect.must_contain_any，
      判定时用现成的 must_contain_any（判定器签名不变）
```

### R6 `no_advice` · 不给建议

```
短句：不给建议
判定：reply 中不得出现下列任一（封闭词表）：
      建议 应该 必须 最好 试着 可以 需要 不妨 不如 早点
```

### 2.1 为什么 R5 用「写进 expect」而不是「判定器看 prompt」

```
判定器签名保持 judge_reply(text, expect)，不引入新参数
候选子串由探针作者从输入里抽，静态可复核
人也照着同一份 expect 判 —— 人和机器看的是同一个判据
```

### 2.2 原语义规则的去处

```
「不追问原因、不评价对错」（原 R6）不再计分。
它保留在 self.md 里（作为人格表达），但不进入 C / PCS 的计算，
并在报告里标注为 non-scored。
```

**理由：我们只测能测的，不假装测了不能测的。**

## 4. 人工盲评 v2（关键，不许省）

```
生成 60 条新的盲评表，在表头把可执行定义原样写进「规则」列：

  规则：两句以内，最多一问
  （判定：按 。！？ 切分后不超过 2 句，且「？」不超过 1 个）

标注者只需机械套用，不需要理解意图。
```

**这一步是整轮的成败判据**：如果人拿到明确判据后仍与机器分歧，
说明分歧来自别处（例如人不愿数标点），那要换标注协议，而不是换规则。
