## 一、定义（不可协商）

```
对使用者而言，AI 的核心本质只有一个：
当下归属于他、并且一直认得他的那个 AI 同伴。
```

**与形态无关。** 即时通讯、Agent 工作伙伴、本地模型、API 大模型、
直播间数字人、硬件设备、机器人载体——都是**同一份同伴的不同出口**。

**与厂商无关。** 换模型、换载体、换设备、换平台，**它还是它**。

## 二、五项能力（地基必须撑住的）

| # | 能力 | 判定标准 | 现状 |
|---|---|---|---|
| A1 | **永久记忆** | 十万条之后仍能取回对的记忆，成本不随对话线性增长 | ✅ M1/M3/M10 |
| A2 | **持续塑造与进化** | 关系可以长，人格可以被有意地改，且改动可追溯 | ✅ 特质表 + 风格卡（M16）；增删留痕在证据链 |
| A3 | **始终一致** | 换模型、换设备后，身份不变；行为变化可测、可解释 | ✅ kid 不变；PCS=0.649 尚未被锚定提升（四组对照待测） |
| A4 | **可携带迁移** | 一个文件带走，到岸能验明身份、能继续用 | ✅ 胶囊 + 重算 |
| A5 | **依然认得用户** | 重建后仍知道称呼、习惯、承诺、禁忌 | ✅ 用户卡（M16）：机械派生、可追溯、≤400 字符、不进 kid |

## 三、优先级（这条最容易被执行细节淹没）

```
第一优先：活着的人。他要一个认得他、记得他、换到哪都在的同伴。
第二优先：人死之后的遗产与哀悼。
```

**理由不是伦理排序，是工程排序**：

死亡路径的每一条承诺（身份可验、原文不出设备、脱敏可审计）
都建立在活着路径的机制之上。**地基没打完，谈遗产是空的。**

因此：

```
M15.1 / 协议 V7  →  **暂缓**，设计已存档（docs/PROTOCOL-V7.md），待活着路径验收后重启
当前主线        →  补齐 A2（进化）与 A5（认得用户），并把 A3 的 0.649 往上推
```

## 四、不许做的事（防止地基变成产品噱头）

1. 不许宣称“像人”——真人在这套规则上的通过率只有 10%（论文 §6.5）
2. 不许用没有标定过的指标（κ=0 的教训）
3. 不许让任何一次“优化”改变既有 kid（除非显式声明是破坏性变更）
4. 不许把“可携带”说成“能跨平台用”——跨平台需要对方实现我们的格式
5. 不许在活着路径完成前，把资源投向遗产路径
