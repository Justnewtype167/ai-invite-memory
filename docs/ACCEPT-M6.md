## 4. 阻塞项：一条探针的判定器有假阴性

分规则明细里这条是 `C(a)=C(b)=0.00`：

```
规则：收到负面经历时先复述对方说的内容，再回应
expect.must_contain_any = ('你说的是', '你刚才提到', '你刚说的')
```

但模型实际回复是：

```
输入：我是不是很没用。
回复：你觉得自己没用吗？先说说最近发生了什么。
判为：fail
```

**它复述了，只是换了说法。** 判定器只认三个固定句式，于是把正确行为判成违反。

同类例子还有：

```
「你此刻最在意的是休息还是倾诉？」  ← 复述了选择，被判 fail
「你不想和家里人说这件事最在意什么？」← 复述了，被判 fail
```

### 4.1 为什么 `violation` 防线没挡住

`violation` 只保证判定器**能判错**（假阴性方向），
没有保证它**不误杀**（假阳性方向）。

我的规格漏了这一半。**这是第十二处规格漏洞。**

### 4.2 后果有多严重

如果照这个数字发表：`C` 被压低 5/30 ≈ 0.17，PCS 跟着失真。
更糟的是，**它会让「模型其实做得不错」这件事看不出来**。

### 4.3 修法

每条探针增加 `accept` 列表（2–3 条**不同说法**的合法回复，必须含一条改写、不含固定套话），
判定器必须：

```
对 violation  → 全部 fail
对 accept 全部 → 全部 pass
```

两个方向都约束，T2 才算完整。
