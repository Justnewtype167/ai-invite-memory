## 2. 结论一：特质与风格卡**降低**了一致性（负结果）

```
PCS：A 0.7012 → B 0.6587 → C 0.4894
降幅远超噪声：现有 95% CI 宽度约 0.23
```

**这推翻了我们自己的假设**：以为「告诉模型他该怎么说话」会让它更像原来那个。

| 观察 | 可能原因 |
|---|---|
| `C(glm)` 从 0.925 掉到 0.675 | 风格指导把 glm 推离了规则集（短、先答、不评价） |
| `A` 从 0.825 掉到 0.725 | 两个模型对同一段指导理解不同，反而分叉 |

**最可能的原因**：风格卡与 PCS 规则**目标不一致**——
风格卡要求「像他」，规则要求「守规矩」，在小模型上互相拉扯。

## 3. 结论二：用户卡是唯一有正收益的（强正结果）

```
事实命中率：A/B/C ≈ 0.00 → D = 0.9167
token 代价：30.0 → 31.9（+6%）
```

> 400 字符的用户卡，把「它认得你」从 0 提到 92%，每轮只多 1.9 个 token。

D 组 PCS 还从 0.4894 回升到 0.5439，说明卡不只是加信息，
**它还修正了风格卡带来的部分偏移**。

## 4. 结论三：复读守卫全程为 0

四组 `echo = 0.0000`：风格卡没导致照抄模板。守卫没被触发，但机制在位。

---

## 5. 这对产品意味着什么

| 组件 | 建议 |
|---|---|
| **用户卡** | **默认开启**：唯一有正收益，成本 +6% |
| 特质 | 默认关闭；只作为用户主动要求的开关 |
| 风格卡 | **默认关闭**：在当前判定集下有害；要启用必须先改判定口径 |

**关键洞察**：风格卡不是坏东西，是**它和我们的判定集目标冲突**。
要么让「像他」进入评判标准，要么别用它。
