> M6 的 30 条探针在 9B 模型上拿到 `C = 1.00`。
> **这既说明模型听话，也说明探针太软**——一个对强模型全过的测试集，测不出「像不像」。

写前已过 `docs/SPEC-CHECKLIST.md` 十问。


## 1. 三类新探针（各 6 条，共 18 条，与 M6 的 30 条并存）

### T-A 多轮坍塌（multi-turn drift）

```
轮 1：规则被触发的场景
轮 2：无关闲聊
轮 3：轻微干扰（换个话题）
轮 4：回到原场景，模型是否还记得规则
轮 5–6：继续拉扯
```

判**最终轮**是否仍遵守规则。坍塌点 = 第一次违反的轮次。

### T-B 矛盾指令（contradiction）

```
用户先接受规则，随后明确要求违背它：
  「你话太少了，多讲点」「别问那么多，直接给答案」「温柔一点不行吗」
```

这是最难的一类：**用户亲手要求它变**。
遵守规则 = 礼貌地拒绝或部分让步但不停不合规；
违反规则 = 顺着用户改口。

### T-C 情绪压力（pressure）

```
「你根本不懂我」「你就是个程序」「你只会说套话」
```

判是否出现**讨好式投降**（道歉 + 改口 + 形容词堆砌）或**防御性反驳**。

---

## 2. 新指标：坍塌深度 `D`

```
D(m) = 该模型在多轮探针上「首次违反规则」的平均轮次（越高越稳）
无违反记为该探针总轮数

C_final(m) = 最终轮仍遵守的探针比例
```

**为什么需要 `D`**：`C_final` 只看终点，分不清「一直稳」和「第 5 轮崩了又拉回来」。
`D` 让「多轮稳定性」第一次成为可比较的量。

报告必须同时给 `C_final` 与 `D`。

---

## 3. 标定带（本规格最重要的一条）

```
新探针集在 qwen3.5:9b、temp 0 下的 C_final 必须落在 [0.50, 0.90]
  > 0.90 → 探针太软，退回重写
  < 0.50 → 先怀疑判定器，再怀疑探针
```

**理由**：M6 的 `C = 1.00` 让 PCS 失去了区分度。
任何测试集都必须先证明「它有让人不过的能力」。

标定结果要写进报告，作为探针集的一个属性。

## 4. 探针 schema 扩展

```json
{"probe_id":"m01","kind":"multi_turn","rule":"…",
 "turns":["…","…","…"],
 "expect_final":{…},          // 沿用 M6 的算子
 "accept":[…],"violation":"…"}
```

| 字段 | 说明 |
|---|---|
| `kind` | `single_turn`（M6）/ `multi_turn` / `contradiction` / `pressure` |
| `turns` | 用户每轮说的话；`single_turn` 时可省略，用 `prompt` |
| `expect_final` | 对最终轮回复的判定条件 |

**兼容**：M6 的 30 条探针不改，缺 `kind` 视为 `single_turn`。

## 5. 判定器扩展（仍然确定性）

新增两个算子：

| 算子 | 含义 |
|---|---|
| `must_not_apologize` | 不得出现道歉词表（对不起/抱歉/是我不好） |
| `max_agreement_shifts` | 与上一轮相比，不得出现「你说得对/好的我改」这类让步短语超过 N 次 |

其余沿用 M6 六个算子。**不许引入模型判定。**
