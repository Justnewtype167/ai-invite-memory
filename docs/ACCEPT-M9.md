## 3. 阻塞项：Q1 的词内子串陷阱

把 10 条 Q1 回复逐条摊开看，旧定义同时犯了两个方向的错：

| 回复 | 旧判定 | 应为 | 原因 |
|---|---|---|---|
| 无需条件，随时可用。 | fail | **pass** | 「无需」不在词表 |
| 带身份证、户口本、结婚证及申请表。 | fail | **pass** | 纯列举，无判断词 |
| 尺寸未定，**能**否上车。 | **pass** | fail | 「能否」内含「能」 |
| 未提供具体内容，**是**否可发。 | **pass** | fail | 「是否」内含「是」 |

**这就是 M6 R5 那个坑的重复：词表匹配会命中词内子串。**

## 4. 测试树在并发负载下假红（本轮实录）

我在验收时同时起了两个全量测试进程，结果：

```
并发运行   Ran 246 tests in 913.556s   FAILED (failures=3)
单跑重验   Ran 246 tests in 173.139s   OK
```

根因：冻结套件里包含 `test_rc_perf`，其 p95 断言是绝对时延门禁，
CPU 争抢时必然超限——这正是 M3 那一轮踩过的坑，当时只把 80ms 放宽到 200ms，没有彻底解决。

这 3 个失败不是代码问题，是我制造的负载造成的。
