# 地基不变量：为实时、具身、仿真形态预留的接口

> 目标：**无论输出形态怎么变，地基不变。**
> 本文档定义「什么必须不变」「什么必须泛化」「怎么泛化」，并标注当前实现状态。

---

## 1. 四条永远不变的契约

```
C1  证据只追加、哈希链、字节可复现          → 与模态无关
C2  内核 = 证据 + 策略的纯函数，产出 kid     → 与模态无关
C3  单向派生：上层永不反向写回              → 与形态无关
C4  身份 = 内容哈希；行为 = 对声明规则的符合度 → 与形态无关
```

**当前状态：四条全部实现并有测试（246 个）。**

这四条之所以与形态无关，是因为它们从未提及「文本」「句子」「对话轮次」——
它们只提及**证据**与**派生**。

---

## 2. 三处目前是「文本专用」的，必须泛化

### 2.1 事件载荷（现在：`text` 内联）

```
现状  {"id":"ev_000123","type":"turn","text":"我今天很累。",...}
问题  文本是内联的，音频帧、动作序列、传感读数无处安放
```

**改造方向：信封 + 内容寻址载荷**

```
{"id":"ev_000123","t":"...","type":"turn",
 "modality":"text|audio|vision|action|sensor",
 "payload":"sha256:ab12...",        ← 载荷存 blobs/，按内容寻址
 "summary":"我今天很累。",          ← 可选短文本，仅供检索与预算装配
 "prev":"...","hash":"..."}
```

**为什么这样能保住地基**：事件仍然只有哈希链可验证的元数据，载荷不可改（内容寻址），
而检索层仍然只读 `summary`——**4k 预算的机制完全不用改**。

### 2.2 行为身份（现在：文本算子）

```
现状  规则是「问号数」「字数」「含子串」——对语音与机器人失效
```

**改造方向：把 PCS 定义在「轨迹」上，而不是「文本」上**

```
投影器  projector(kernel, context) -> trace
轨迹    trace = 有序的类型化片段：
          text   → token 序列（现在）
          audio  → 音素/停顿/语速特征
          action → 动作原语序列，含时长
评判    PCS 规则按模态注册：同一套 A × min(C)，算子换一套
```

**关键点：规则集随模态扩展，但 PCS 的公式与门槛不变。**

### 2.3 实时性（现在：批式全量编译）

```
现状  每次编译扫全部证据；查询 p50 13ms，但没有流式增量
问题  连续流场景下 O(全部) 不可接受
```

**改造方向：增量编译 + 定期全量对账**

```
增量  以上次 kid 为水位，只处理新证据 → 产生 kid'
对账  每 N 次（或每夜）做一次全量重算，断言 kid' == kid_full
      —— 这条对账就是「增量没有破坏确定性」的证明
```

## 3. 具身形态需要新增的一层：动作闸门

```
现状  闸门 G1–G5 只挡「写内核」
必须  具身形态下，拒绝必须是物理的：不执行动作、不发声
```

**新增 A 层：actuation gate**

```
输入  内核的 canon（不可变条目）+ 本次要发出的动作/语音
判定  违反 canon 的动作一律不发出，并写一条 refusal 事件进证据层
意义  「不可腐蚀」从「拒绝改自己」扩展到「拒绝做违反自己的事」
```

**这一层没有它，具身形态下的伦理承诺是空的。**

> **当前状态：未实现（M13 才做）。**
> 现在投影是纯函数，因此**「它做过什么动作」没有任何记录**——具身形态下等于没有审计线。
> 这条已记入 `docs/AUDIT-01.md` 的 P1-A3。

## 3.5 一个必须说清的边界：行为身份不可携带

```
胶囊能带走：证据 + 身份（kid）
胶囊带不走：行为身份（PCS）
```

`jian_pcs` 的输入是**回复集文件**，不读 store。这意味着：

```
拿到胶囊的人能验证「这是不是同一个人」（重算 kid）
但不能独立验证「它表现得像不像」（PCS 需要那份回复集）
```

**PCS 是评测结果，不是可携带的证据。** 这不是缺陷（评测本就依赖采样），
但任何对外承诺都不能说「把行为一致性也一起带走」。

## 4. 通用性的可验证命题（这才是“地基通用”的证明方式）

```
P1  同一份证据 + 同一策略 + 不同投影器  → kid 相同，轨迹不同
P2  换设备、换模型、换形态             → kid 不变
P3  删掉内核重建                      → kid 不变
P4  增量编译 vs 全量编译               → kid 相同
```

**P1 是回答「具身通用吗」的唯一实证**：
同一份 kid 驱动两套完全不同的输出（一段文字 / 一段动作序列），
而身份哈希没变——这证明形态在投影层，不在人格里。

## 5. 实施顺序（按“能立刻证明通用性”排序）

| 阶段 | 内容 | 能证明什么 | 状态 |
|---|---|---|---|
| M10 | 信封 + 载荷改造（文本仍唯一模态） | C1/C2 与载荷无关 | 未开始 |
| M11 | 轨迹契约 + 双投影器（文本 + 规则化动作） | **P1** | 未开始 |
| M12 | 增量编译 + 对账 | P4 | **完成**（v0.15-m12） |
| M13 | 动作闸门 | 伦理在具身成立 | 未开始 |
| M13 | 动作闸门（refusal 进证据） | 伦理在具身成立 | **完成**（v0.16-m13） |
| M14 | 会话级等价装配 + 分块输出 | 实时形态的第一半 | **完成**（v0.17-m14，**但不是计算增量**，见下） |
| M14.1 | 冻结 bm25 统计量的会话装配 | 真正的计算增量 | 未开始，需先决定 S1 的口径 |
| M15 | 实时音频流 | 语音形态 | 未开始 |

### 关于 M14 的一句必须公开的话

```
M14 做到了：会话内等价（与全量逐字节相同）、分块输出、索引增量更新
M14 没做到：跳过装配计算。因为装配的 bm25 依赖全库 idf/avgdl，
            追加一条事件会改变所有分数——字节等价与「跳过重算」互斥。
```

**这是规格本身的张力，不是实现偷懒。** M14.1 若要真正的计算增量，
必须先把 S1 从「与全量字节等价」改成「与冻结统计量的全量等价」，
那是口径变更，不是优化。

**建议先做 M10 + M11**：它们合起来就能给出 P1 的实证，
而 P1 正是「地基通用」这句话的全部证据。

## 6. 一句话

> 地基之所以不会过时，不是因为它预见了机器人，
> 而是因为它只承诺了两件与形态无关的事：**证据可验证、身份可重算**。
> 其余的（说什么话、发什么声、做什么动作）全部属于投影层，可以随时换。
