## 2. 硬伤（P1）：动作映射只认三条固定措辞

我用**真实风格**的指令造了一个内核：

```
说话短一点 / 别老夸我 / 不用每次都问我在干嘛 / 别叫我宝贝
→ canon 4 条，全部正常
→ text_v1 投影成功（5 段）
→ action_v1 失败：E_PR_EMPTY「没有 canon 规则命中动作映射」
```

**映射表是精确字符串匹配，而 canon 来自用户自由输入。**
用户怎么说完全不可预测，映射表永远追不上——覆盖率天花板接近零。

### 更要紧的是：验收记录是一句同义反复

`ACCEPT-M11.md` 的手工记录用了 `不主动联系` / `先复述对方的话` / `不评价对错`——
**恰好就是 `action_map.json` 里仅有的三条。**

```
用映射表里存在的措辞去证明映射能工作 = 只证明了查表能查到
```

这条记录不能作为「具身通用」的证据，必须重做。

## 3. 修法（建议）

```
① action_map.json 增加 _default 条目：未命中的 canon 一律投影为 idle 或 nod
② 匹配方式从「精确相等」改为「关键词包含」，词表仍写在数据文件里
③ E_PR_EMPTY 只在 canon 为空时抛（没有约束 → 投影为空是合理的）
④ 手工记录换成真实风格指令的内核重跑，并写明命中率
```

**先做 ①③ 就能让真实内核投影成功**；②是覆盖率问题，可以做但优先级低。

## 4. 一个建议（P2，不阻塞）

`Segment` 目前没有 `source` 字段，轨迹里看不出「这个动作是哪条 canon 产生的」。
建议后续加 `source: str | None`（存 canon 条目文本或 id），
这样动作轨迹也能被审计，将来把 PCS 定义到轨迹上会需要它。

```
机制：通过（四条不变量成立）
可用性：不通过 —— 真实内核投影会失败
验收：不签 —— P1 修完重做手工记录后再验
```
