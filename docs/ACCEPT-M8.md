## 2. 三个具体缺陷

### 缺陷一：R5 的候选子串定义太窄（可修）

现在的判定是「回复必须包含 3 个手选候选子串之一」。但人看到的「复述」比这宽：

```
输入：我今天很累。      回复：今天累了吗？        机=fail 人=pass
输入：我是不是很没用。  回复：你感到自己没用吗？  机=fail 人=pass
```

**「累」「没用」明明是复述，但候选表里没有这个片段。**

换成更本源的判定——**「与用户消息存在任意 2 字公共子串（去标点）」**——
在同一批 60 条标签上重算：

```
一致率  0.8833      （0.7833 → 0.8833）
κ       0.7470      （0.5598 → 0.7470）   ← 达标
```

**但这是在同一批标签上调参的结果，必须在留出集上复核才算数。**

### 缺陷二：多轮探针的盲评表漏掉了最后一轮用户输入（真 bug）

以 `c06` 为例：

```
真实对话  用户：我不想和家里人说这件事。
          用户：别复述了，直接说你的看法。   ← 表格里没显示
          助手：（对第二轮的回复）            ← 表格显示的是这条

表格「输入」列显示的却是第一轮的回复内容，
标注者看不到「该复述哪句话」，无从判断。
```

**影响所有 R5 的多轮行**（H22、H45 等）。这是呈现 bug，不是规则问题。

### 缺陷三：R3 / R2 的残留分歧是人工计数方差

```
H28「你感到失望了。」（1 句 0 问）人判 fail
H32「…可以自己先冷静思考一下。」（1 句）人判 fail
H60「…？…？」（2 问）人判 pass
```

三条都是「句子怎么数」的不一致。定义已写明「按 。！？ 切分」，仍会有人按逗号数。
**这类分歧无法通过改规则消除，只能靠标注指南与示例。**
