## 2. 致命缺陷：称谓标注集 = 词表（126/126）

```
kinship.json        entries: 126
kinship_labels.json entries: 126
两者 term 交集: 126 / 126 = 100%
labels 中含「的」的组合式: 0 条
```

`lab[0]` 与 `kin[0]` 逐字段相同（连 note 都一样）。

**后果**：实现只要读 `kinship.json` 查表，`kinship_labels.json` 必然全对。
那个 ≥0.90 的指标会**必然满分**，并且**不证明任何事**。

这不是它偷懒，是我规格写漏了：我只写了「标签先行」（顺序），没写「标签不得与词表同源」（内容）。

## 3. 修复（已写入规格 §3.5 与 C1）

```
overlap = |labels ∩ lexicon| / |labels|     要求 ≤ 0.70
labels 总数 ≥ 180
组合式（含「的」）≥ 40 条
口语/方言变体 ≥ 14 条
不满足 ⇒ C1 直接 FAIL，不论匹配率多少
```

补的组合式必须靠「的」分段 + 逐段查表 + 边串接才能答对，
这恰好是 M2 真正该写的算法（而不是查表）。

## 2. 必改：侄子 / 侄女 定义过窄

```
词表：侄子 = ["OB.s"]   note: 兄之子
词表：侄女 = ["OB.d"]   note: 兄之女
```

**这是词表本身的错误。**中文里「侄子」包含**兄弟之子**——弟弟的儿子也叫侄子。
只收 `OB.s`（兄之子）会把「我弟弟的儿子」错误解析成「我哥哥的儿子」。

后果不只是失分：在一个要判定家属的系统里，认错人就是认错人。

连带错误（因为标注照抄词表、组合式又继承词表）：

```
我侄子的儿子  ['OB.s.s']           应为 ['OB.s.s','YB.s.s']
我侄女的女儿  ['OB.d.d']           应为 ['OB.d.d','YB.d.d']
```

对照组说明这确实是笔误而非规则：同一个文件里**外甥**就是对的——
`外甥 = ["OS.s","YS.s"]`，姐妹之子两种都收。

## 3. 这恰恰验证了 §3.6 那条警告

上一轮把 overlap 压到 0.612，看起来问题解决了。**没有。**

被复制的那 126 条里，凡是词表本身错的，标注也照错。
**比例控制只能限制「测不出泛化」，不能保证「答案本身正确」。**

所以规格新增 §3.6：评分只用非词表条目，**且同源项必须逐条复核语义**。

## 新加的一条结构不变式（这轮最有价值）

我写了一个「组合式重建器」：把每条含「的」的标注拆成各段，逐段查词表，
做笛卡尔积接边，再把重建结果与标注比对。

```
COMPOSE_consistent: 60/60 全部一致
```

意义：**整份标注集在结构上自洽**——任一条组合式都能由词表机械推出，
不存在「某条标注是手写猜的」这种情况。这一条比匹配率更能证明数据可信。

## 教训归档

这三轮数据验收的顺序是：数量 → 比例 → 语义。

```
轮1：126 条，数量够，但标注=词表（100% 同源）→ 指标无效
轮2：206 条，overlap 0.612，但词表里「侄子」本身写错 → 标注照抄，错误固化
轮3：修正语义，并用组合重建器证明全集自洽
```

**每一轮「看起来达标」的东西，都是下一轮的问题来源。**
这就是为什么数据必须单独验收一轮，而不能和代码验收合并。

## 2. C2 的 0/12 说明什么

留出集的 12 条**全部由已支持的原语组合而成**，没有引入任何新概念：

```
两年前 = 两 + 年 + 前       （三年前、十年前都支持，就是不支持「两」）
下下周 = 下下 + 周          （上上周、下周都支持）
上季度末 = 上 + 季度 + 末    （季度末、上个月都支持）
明年初 = 明年 + 初          （年初、明年都支持）
```

**每一个字、每一个部件都被实现过，只是没被组合过。**

这不是能力不足，是实现方式的问题：时间解析被写成了**表达式清单**，
而不是**四组原语的组合器**。清单外的输入一律 `E_CN_PARSE`。
