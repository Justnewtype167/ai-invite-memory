# M5 路线：LLM 进链路之后，确定性怎么守

> 这是一个**决策文档**（ADR 风格），不是规格。定了之后才写 TASK-06。
> 写之前已过 `docs/SPEC-CHECKLIST.md` 十问。

---

## 0. 先把「确定性」拆成三种，否则永远吵不清

| 级别 | 含义 | 能不能守 |
|---|---|---|
| **D1 字节一致** | 同一份证据重算，`kid` 一字节不差 | 现在（M4）就有 |
| **D2 提案可重建** | 同一份对话重跑，模型产出同一批提案 | **本地可达，API 不可达**（见下） |
| **D3 行为等价** | 换模型/换时间，人格行为落在阈值内 | 可以，靠 PCS 度量 |

**关键判断：M5 必须守 D1；D2 只在本地模型这一侧当作「工程福利」，不能写进承诺。**

### v0.2 修订（实测推翻了原判断）

原判断是「D2 做不到」。2026-10-30 在 `qwen3.5:9b`（Q4_K_M / llamacpp）上实测：

```
temp 0.0, seed 42, 同一 prompt 连跑 3 次   →  3/3 输出逐字相同
temp 0.7, seed 1..5, 同一 prompt           →  5/5 输出互不相同
```

准确的表述：

| 环境 | D2 |
|---|---|
| 本地模型 + temp 0 + 固定 seed + 固定权重 | **本机实测可复现** |
| 同一权重、换 GPU / 驱动 / 后端版本 | 不保证 |
| 云端 API（哪怕 temp 0） | **不保证**（批处理、路由、静默升级） |

**结论：D2 不是做不到，而是「只在你自己掌控的那台机器上做得到」。**
这恰好又是「本地优先」的一个硬理由——它不只是隐私和成本，还是**可复现性**。

## 1. 三条路线

### A · 提案即证据（Proposal-as-Evidence）

```
LLM 输出 → 写成 proposal 事件（进证据层、进哈希链）
compile 只读证据，包括 proposal
kid = f(证据含 proposal)
```

- 守 D1：**能**。提案是证据的一部分，重算必然一致
- 能力：强（模型想说什么就记什么）
- 代价：证据变大（每次编译 ~400 token）；换设备时提案必须一起搬
- 风险：**「AI 写自己的证据」** —— 必须靠闸门挡住，提案不能直接变 canon

### B · 规则兜底（Rule-Gated Proposal）

```
LLM 只产出候选条目 → 规则校验/规范化 → 通过才提交
不通过的候选：丢弃，并记一条 rejected 事件（留审计）
```

- 守 D1：**能**，且比 A 更强（提交函数是纯规则）
- 能力：弱于 A（规则表达不了的东西提不进去）
- 代价：低
- 风险：规则太严会把模型变成摆设，太松等于回到 A

### C · 双层内核（Two-Layer Kernel）

```
kid 只覆盖确定性层（canon / state / graph / self 骨架）
风格层（style.md）单独版本、不进 kid、允许 generation=1
```

- 守 D1：**能**（把不确定性赶到 kid 之外）
- 能力：强，且可以每轮都变风格
- 代价：**身份被掏空**——kid 里没有「他怎么说话」，只剩「他认什么」
- 风险：产品卖点变成「价值观可复现、性格不可复现」，与叙事冲突

## 2. 六维对比

| 维度 | A 提案即证据 | B 规则兜底 | C 双层内核 |
|---|---|---|---|
| D1 字节一致 | ✅ | ✅ | ✅ |
| 模型能力上限 | 高 | 中 | 中高 |
| 证据体积 | +40% | +5% | +5% |
| 可审计（哪句话来自哪个提案） | ✅ 天然 | ⚠️ 需额外记录 | ❌ 风格层不可溯 |
| 换设备成本 | 提案必须搬 | 低 | 低 |
| 与「人格可迁移」卖点的一致性 | 高 | 中 | **低** |

## 3. 一个必须先想清楚的区分：kid 与 PCS 量的是两件事

```
kid  = 内容身份：这份人格是不是同一份字节
PCS  = 行为身份：换模型后，像不像同一个人
```

**换模型后，kid 一定会变**（提案不同），**但 PCS 应该仍然高**。
这两件事同时成立，才是「可迁移」的正确定义：

> 身份锚在证据上（kid 可验），行为锚在测试上（PCS 可测）。

如果只有 kid，你会得到「一换模型就不是同一个人」；
如果只有 PCS，你会得到「没有真相、只有印象」。**两个都要。**

---

## 4. 推荐：A + B 为主，C 只用于不进身份的部分

```
身份层（canon / state / graph / self 骨架）
  → A：提案入证据，可审计、可重算
  → B：提交由规则控制，闸门仍是 G1–G4 加一条 G5

风格层（语气、口癖、节奏）
  → C：不进 kid，单独版本，允许每轮变
  → 但要受「不可腐蚀条款」约束：风格可适配，底线不可动
```

### 为什么不是「纯 A」

纯 A 等于把闸门交给模型——它写什么提案，什么就成 canon。那正好废掉 M4 的全部工作。

### 为什么不是「纯 C」

纯 C 会让 kid 里容不下「他是怎么说话的」，而那是陪伴产品最被感知的部分。
**把最容易感知的东西排除在身份之外，等于自己承认身份不重要。**

---

## 5. 这份决策要求接口改三处

| 改动 | 内容 |
|---|---|
| 新增事件类型 `proposal` | 字段：`text`（提案正文）、`target`（要改的条目名）、`model`、`prompt_sha` |
| 新增门控 G5 | 提案必须能映射到已存在的条目名，且 `model` 非空；否则拒绝 |
| 新增 `META.origin` | 取值 `proposal` / `rule_fallback`；**回退会改变 kid**，不许静默等价 |

`--allow-fallback` 的含义要写死：**允许在缺提案时用规则兜底，但 kid 会不同，且 META 标注 origin=rule_fallback。**

---

## 6. 三个反例（写规格时必须挡住）

1. **模型自封**：提案写「我是人类」→ 试图改 canon → 必须被 G1 挡住（canon 只能由 directive 事件改）
2. **静默回退**：新设备没有提案，compile 悄悄用规则兜底 → 同一个 kid 却是不同内容 → **必须让 kid 变化并标注 origin**
3. **提案洪泛**：模型每轮写 20 条提案把证据撑爆 → 需要配额（每编译一次最多 N 条，超出拒绝并记事件）

## 8. 一句话

> **不确定性不是被消灭的，是被关进证据层的。**
>
> 模型的每一次提议都变成一条可签名、可审计、可重放的记录；
> 而「它能不能成为人格的一部分」由规则决定。这就是 M5 的全部。
