# TASK-21 · 特质、风格卡与用户卡（M16）

> 目标：把「像他」「认得他」「还是他」这三件事，做成**可写入、可审阅、可测量**的东西。

---

## 0. 三个派生品，一条红线

```
特质表    声明式：想要什么性格（来自用户/运营，不来自模型）
风格卡    蒸馏式：他平时怎么说话（从历史蒸馏，一次）
用户卡    机械式：它该记得的用户事实（从证据确定性派生）
```

### 红线：三个都不进 kid

```
kid = hash(self_md, canon_md, state, graph, origin, models)
这三样只影响**生成与装配**，不影响**身份**。
```

**理由**：用户卡会随对话频繁更新。若它进 kid，身份就天天变——
这与宪章 A3「始终一致」直接冲突。

**代价**：它们不是身份的一部分，所以重新派生可能得到不同结果。
因此：能机械派生的必须机械派生（用户卡），不能的必须一次性写入并留痕（风格卡）。

---

## 1. 两条不可协商的前提

### 1.1 特质只能由人写入

```
禁止：模型输出 → 抽取特质 → 写回人格
理由：这是「人格逐代腐坏」的精确形式——
     三个月后人格变成模型自己的口音，且从未被人批准
```

入口只有两个：`directive/lock`（用户操作）、`proposal`（人工批准）。

### 1.2 三者都不进 PCS

```
可判定：「问号数 <= 1」「字数 <= 40」
不可判定：「毒舌」「闷骚」「像他」
```

把不可判定的东西塞进 PCS，κ 会掉回 0（M8 已付过代价）。

## 2. 特质表

`jian_kernel/data/traits.json`：

```json
{
  "可爱": {"guidance": "多用短句与语气词，允许叠词；不卖萌到影响语义",
           "conflicts": ["毒舌", "高冷"], "modes": ["support","banter"], "risk": "low"},
  "毒舌": {"guidance": "可以调侃与反讽，但不针对外貌、家人、收入",
           "conflicts": ["可爱","温柔"], "modes": ["banter"], "risk": "high"},
  "闷骚": {"guidance": "嘴上克制，偶尔露一两句真心话；不解释自己",
           "conflicts": [], "modes": ["support"], "risk": "medium"}
}
```

| 约束 | 值 |
|---|---|
| 同时生效上限 | **5 条** |
| 冲突 | 必须显式解决，并在 `self.md` 写明哪条胜出 |
| 高风险 | 非允许模式下一律不生效（毒舌禁入咨询/客诉） |

## 3. 风格卡（一次性蒸馏）

```json
{
  "source": {"from_event": "ev_000120", "to_event": "ev_000620", "count": 501},
  "distilled_at": "2026-11-02T00:00:00Z",
  "model": "qwen3.5:9b", "prompt_sha": "sha256:...",
  "rhythm": "句长 8-22 字；少用感叹号；一段常只有一句",
  "address": "叫我「老周」，自称「我」；从不用「您」",
  "tics": ["嗯…", "算了"],
  "examples": ["…"], "counter_examples": ["…"],
  "forbidden": ["宝贝", "亲爱的"]
}
```

| 规则 | 值 |
|---|---|
| 上限 | **800 字符**（超即拒绝写入） |
| examples / counter | ≤15 / ≤3 |
| 脱敏 | 第三方发言不得进入任何字段（复用 M15 规则） |
| 写入即证据 | 作为 `proposal` 入链，之后不可改（改就是新提案） |

### 3.1 复读守卫（可判定）

```
生成的回复与 examples 任意句的最长公共子串 <= 12 字
超过即判定为「抄模板」，记一次违规
```

**没有它，给了示例的模型最省力做法就是照抄。**

## 4. 用户卡（新增：解决 A5「依然认得用户」）

### 4.1 定位

```
问题：现在内核有 state（认识 301 天 / 4 条事件 / top_kinship）
     但装配上下文时没有「用户是谁」的显式条目
     ⇒ 换载体后它记得天数，不记得「你讨厌被叫宝贝」
做法：一张 <= 400 字符的用户卡，固定钉在上下文里
```

### 4.2 结构（全部可机械派生）

```json
{
  "address": {"call": "老周", "self": "我", "never": ["宝贝", "亲爱的"]},
  "people":  [{"relation": "母亲", "name": "张兰"}, {"relation": "同事", "name": "小李"}],
  "taboos":  ["不提家庭矛盾", "不问收入"],
  "promises": [{"text": "答应陪他去看海", "since": "2026-09-01"}],
  "ongoing": ["在准备考试", "在找新工作"],
  "prefs":   {"like": ["晚上聊", "简短"], "dislike": ["香菜"]}
}
```

| 字段 | 来源（**必须可机械派生**） |
|---|---|
| `address` | `jian_cn` 称谓解析 + 用户显式 directive |
| `people` | `jian_cn` 亲属/称谓表 + 证据中出现的关系词 |
| `taboos` | `directive/lock` 事件（用户说「别提…」） |
| `promises` | `is_promise` 的未完成承诺 |
| `ongoing` | 近期 `milestone` / 高频话题（规则统计，不用模型） |
| `prefs` | 用户显式表达（「我不吃香菜」）→ canon 派生 |

**关键约束：用户卡不许由模型自由发挥。** 每个字段都必须能追到一条证据。
没有证据的字段留空，而不是猜。

### 4.3 三条硬规则

```
① 可重算：同一份证据 → 同一张卡（字节级相同）
② 有预算：<= 400 字符，装配时 pinned，不被检索挤掉
③ 不进 kid：卡片更新不改变身份（见 §0）
```

---

## 5. 一条共用派生管线

```
evidence ──┬─→ 用户卡（机械派生，确定性）
           ├─→ 风格卡（模型蒸馏，一次性写入 proposal）
           └─→ 特质（人写入 directive/proposal）
三层都：可追溯来源 + 可审阅 + 不进 kid
```

**分三次做会把同一条管线写三遍——所以合成一个里程碑。**

## 6. 四组对照（这一轮的真正产出）

| 组 | 条件 |
|---|---|
| A | 裸内核（现状，PCS=0.649） |
| B | + 特质（≤5 条） |
| C | + 特质 + 风格卡 |
| D | + 特质 + 风格卡 + 用户卡 |

```
模型对     qwen3.5:9b 与 glm4:9b 交叉
探针       80 条（沿用现有集合，与 0.649 可比）
用户事实集  30 条（例如「我妈叫什么」「我讨厌吃什么」）
指标       PCS / C / A / 用户事实命中率 / tokens每轮 / 复读率
判据       ΔPCS > 0.13 或 Δ事实命中率 > 0.15 才算有效
```

**判据写死**：现有 PCS 的 95% CI 宽 0.232，小于它的提升不能宣称。

## 8. 禁止

1. 不许从模型输出自动生成特质
2. 不许把特质 / 风格 / 用户卡写进 PCS 规则集
3. 不许让三者进入 kid
4. 不许每轮重读原始 500 条（只许读卡）
5. 不许让用户卡出现无证据支撑的字段
6. 不许用墙钟断言（C14）
