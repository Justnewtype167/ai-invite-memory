# TASK-21 · 特质词表与风格卡（M16）

> 目标：让「性格」和「说话方式」变成**可写入、可追溯、可对照测量**的东西。
> 一句前提：**特质与风格都不进判定集**——它们是生成指导，不是可判定规则。

---

## 0. 为什么单独立项

```
现状  人格有 canon（可判定规则）+ self（统计摘要），但没有「说话风格」的可写入载体
问题  换模型后风格跑偏无法纠正，也无法度量「纠正了多少」
做法  特质表（声明式）+ 风格卡（从历史蒸馏）+ 复读守卫（可判定）+ 三组对照（可测量）
```

---

## 1. 两条必须先钉死的红线

### 1.1 特质只能由人写入，绝不自动晋升

```
禁止：模型输出 → 抽取特质 → 写回人格
理由：这是「人格逐代腐坏」的精确形式——
     三个月后人格变成模型自己的口音，且从未被人批准
```

**允许的入口只有两个**：

| 入口 | 谁触发 | 留下什么 |
|---|---|---|
| `directive/lock` 事件 | 用户/运营操作 | 事件 id + 操作者 |
| `proposal` 事件 + 人工批准 | 运营审核 | 提案 id + 批准记录 |

### 1.2 特质与风格不进 PCS

```
可判定：「问号数 <= 1」「字数 <= 40」「不含『宝贝』」
不可判定：「毒舌」「闷骚」「幽默」
```

**把不可判定的东西塞进 PCS，κ 会立刻掉回 0**（M8 已付出过代价：κ 0.603 → -0.003）。

## 2. 特质表（数据驱动）

`jian_kernel/data/traits.json`：

```json
{
  "可爱": {
    "guidance": "多用短句与语气词，允许叠词；不主动卖萌到影响语义",
    "conflicts": ["毒舌", "高冷"],
    "modes": ["support", "banter"],
    "risk": "low"
  },
  "毒舌": {
    "guidance": "可以调侃与反讽，但不针对外貌、家人、收入",
    "conflicts": ["可爱", "温柔"],
    "modes": ["banter"],
    "risk": "high"
  },
  "闷骚": {
    "guidance": "嘴上克制，偶尔露一两句真心话；不解释自己",
    "conflicts": [],
    "modes": ["support"],
    "risk": "medium"
  }
}
```

| 字段 | 语义 |
|---|---|
| `guidance` | 给投影层的自然语言指导（**不是规则**） |
| `conflicts` | 互斥特质名，同时生效即冲突 |
| `modes` | 允许生效的会话模式（复用 M9 的模式字段） |
| `risk` | `low` / `medium` / `high`，高风险特质默认关闭 |

### 2.1 三条强制约束

```
① 同时生效 <= 5 条           否则互相冲淡，结果是没有性格
② 冲突必须显式解决           不是静默丢弃，要在 self.md 写明哪条胜出
③ 高风险特质在非允许模式下不得生效（毒舌禁入咨询/客诉）
```

## 3. 风格卡（一次性蒸馏，不是每轮读 500 条）

### 3.1 为什么不能每轮读

```
500 条 x ~25 token = 12,500 token / 轮
→ 每轮十几倍于现在的 4k 预算
→ 直接推翻「成本不随对话线性增长」
```

### 3.2 卡的结构

```json
{
  "source": {"from_event": "ev_000120", "to_event": "ev_000620", "count": 501},
  "distilled_at": "2026-11-02T00:00:00Z",
  "model": "qwen3.5:9b", "prompt_sha": "sha256:...",
  "rhythm": "句长 8-22 字；少用感叹号；一段常只有一句",
  "address": "叫我「老周」，自称「我」；从不用「您」",
  "tics": ["嗯…", "算了"],
  "examples": ["……"],
  "counter_examples": ["（不像他的说法）"],
  "forbidden": ["宝贝", "亲爱的"]
}
```

| 规则 | 说明 |
|---|---|
| 上限 **800 字符** | 超过即拒绝写入（可判定） |
| `examples` ≤ 15 条，`counter_examples` ≤ 3 条 | 多了模型会复读模板 |
| **必须脱敏** | 第三方发言不得进入任何字段（复用 M15 的 `redaction` 规则） |
| 写入即证据 | 风格卡作为 `proposal` 事件入链，之后不可改（改就是新提案） |
| 重跑不要求相同 | 蒸馏调用模型，不保证确定性；但**一旦写入就不许变** |

### 3.3 复读守卫（可判定，这是关键）

```
生成的每条回复，与 examples 里任意一句的「最长公共子串」
必须 <= 12 字；超过即判定为复读模板，记一次违规
```

**为什么需要它**：给了示例，模型最省力的做法是照抄。这条把「像他」和「抄他」分开。

## 4. 风格卡如何使用（投影层）

```
projector(kernel + style_card, context) -> trace
  风格卡渲染成一段 prompt 片段（字节确定，可测）
  渲染结果不含时间戳、路径、模型名（否则确定性失效）
```

**风格卡不参与 PCS 计分**；它只影响生成，然后用 PCS 观察生成结果是否更稳。

---

## 5. 三组对照（这一轮的真正产出）

| 组 | 条件 |
|---|---|
| A | 裸内核（现状） |
| B | 内核 + 特质（≤5 条） |
| C | 内核 + 特质 + 风格卡 |

```
模型对   qwen3.5:9b 与 glm4:9b 交叉
探针     80 条（沿用现有集合，保证与 0.649 可比）
指标     PCS、C、A、每轮 tokens、复读率
判据     ΔPCS > 0.13（现有 CI 宽度）才算有效；< 0.05 视为噪声
```

**判据写死的理由**：现在 PCS 的 95% CI 宽 0.232，任何小于它的提升都不能宣称。

## 6. 验收（八个）

| # | 测试 | 断言 |
|---|---|---|
| S1 | `test_traits_schema` | 字段合法；未知 mode / 未知冲突名 / 缺 guidance → 对应错误码 |
| S2 | `test_trait_cap_and_conflict` | 第 6 条被拒；`可爱`+`毒舌` 同开 → 按 risk 与优先级解决，并写进 self.md |
| S3 | `test_trait_requires_event` | 没有对应 `directive`/`proposal` 事件时，内核**不含**该特质（防自动晋升） |
| S4 | `test_trait_mode_gate` | `毒舌` 在 `consult` 模式生效 → 拒绝（或强制降级），且报告原因 |
| S5 | `test_style_card_schema` | 800 字符上限、examples ≤15、counter ≤3、字段齐全 |
| S6 | `test_style_card_redaction` | 含第三方发言的输入 → 蒸馏产物不含该原文；脱敏清单随卡记录 |
| S7 | `test_echo_guard` | 回复与 examples 的 LCS > 12 字 → 判定为复读并计数；≤12 不误报 |
| S8 | `test_all_regression` | 现有全部测试全绿；改动在 `ALLOWED_CHANGES` 声明 |

---

## 7. 禁止

1. 不许从模型输出自动生成特质（无人工批准即违规）
2. 不许把特质或风格写进 PCS 规则集
3. 不许每轮重读原始 500 条（只许读风格卡）
4. 不许让风格卡超过 800 字符
5. 不许让第三方发言进入风格卡
6. 不许用墙钟断言（C14）
